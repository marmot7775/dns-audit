# Doc 100: Stop depending on the stub resolver, and say what
# actually failed

Background, verified Oct 12 2026 on the droplet. The audit's
plain resolver copies /etc/resolv.conf at import, which on this
droplet is the systemd-resolved stub, 127.0.0.53. From 15:43 UTC
every NXDOMAIN through the stub timed out while the same query
sent straight to 67.207.67.2 answered in 2 ms. Cause: eth1, the
DigitalOcean private interface, carried the same DNS servers as
eth0 with DNSDefaultRoute on, those servers are only reachable
via eth0, so resolved's eth1 scope failed with No route to host
and a negative answer on eth0 lost to that error. Positive
answers still won, so DMARC, SPF and MX kept working and the
site reported MTA-STS, TLS-RPT and BIMI as Not checked by this
audit on amazon.com, paypal.com, stripe.com, ebay.com,
oracle.com, salesforce.com, adobe.com, nytimes.com and
lanecc.edu, each audit taking 35 seconds, with the card blaming
the domain's nameserver.

Fixed on the droplet, outside the repo, by a drop-in at
/etc/systemd/network/10-netplan-eth1.network.d/no-dns-default-route.conf
containing [Network] DNSDefaultRoute=no, applied with networkctl
reload. Verified: NXDOMAIN through the stub in 3 ms, stripe.com
audit 0.6 seconds with absent, absent, absent.

This doc makes the app survive the next resolver fault and stop
misattributing one. Four parts, in order. Run the full suite
before and after. No new features.

## 1. dns_tools._from_template: never a single stub nameserver

In dns_tools.py, _resolv_conf_template is built from
/etc/resolv.conf. Add a module level function
_upstream_nameservers() that returns the list the audit should
query, in order:

- If config.AUDIT_NAMESERVERS is set (new, comma separated,
  default empty), use exactly that list and stop.
- Otherwise start with the template's nameservers. If any of
  them is a loopback address (127.0.0.0/8 or ::1), replace it
  with the nameservers read from /run/systemd/resolve/resolv.conf
  via dns.resolver.Resolver(filename=...), which lists the real
  upstreams behind the stub. If that file is missing or empty,
  drop the loopback entry.
- Append 1.1.1.1 and 8.8.8.8 unless already present. Public
  resolvers come last so the droplet's own resolvers stay the
  normal path and the public ones only see traffic when those
  fail.

_from_template sets resolver.nameservers from that function.
Keep timeout and lifetime as they are (timeout, timeout times
two). dnspython moves to the next nameserver on timeout within
the lifetime, so one dead upstream costs at most one timeout per
query, not the whole budget. Log the resolved list once at
import at INFO so audit.log shows which servers an audit used.

get_dnssec_resolver already uses its own public list; leave it.

Add config.AUDIT_NAMESERVERS beside the other env settings and
document it in README under configuration with one line: the
nameservers the audit queries, default the system's upstreams
plus 1.1.1.1 and 8.8.8.8.

## 2. /api/health: prove negative lookups work

server.py health returns status, dns_resolution and version. Add
a negative lookup probe: resolve a random label such as
health-<8 hex>.dns-audit.com for TXT with a 3 second lifetime.
NXDOMAIN or NoAnswer means ok. Timeout, SERVFAIL or NoNameservers
means failing. Add the field negative_lookups with the value ok
or failing, and when failing also add negative_lookups_error with
the exception class name. Keep the probe cheap: one query, no
retries, and cache the result for 60 seconds so uptime monitors
polling health do not generate DNS load. dns_resolution stays as
it is for positive lookups. Status stays ok when only the
negative probe fails, so the service is not restarted for a
resolver fault, but the field is there to alert on.

## 3. The uncompleted lookup card blames the right thing

Three places say the domain's nameserver failed when the audit
could not tell who failed:

- result_transformer.py near line 313, the lookup_failed card
  used by MTA-STS, TLS-RPT and BIMI.
- mx_check.py near line 195.
- audit_engine.py near line 6777.

Replace the sentence The nameserver returned a failure or
stopped responding, so this audit did not learn whether the
record exists with: This audit did not get an answer in time.
That can be the domain's nameservers or the audit's own
resolver, and the audit cannot tell which from here. Keep the
rest of each explanation as it is, including that this is not a
finding about the domain and does not mean the record is
missing. Update any test that asserts the old sentence.

## 4. Deploy notes so a rebuilt droplet gets the fix

Add deploy/no-dns-default-route.conf with the exact drop-in
content from the background above, plus a comment line saying
why. Add a step to deploy/README.md: on a droplet with a private
network interface, install that file at
/etc/systemd/network/10-netplan-eth1.network.d/ and run
networkctl reload, then confirm with dig +time=5 +tries=1
zz-probe.mozilla.org TXT that NXDOMAIN comes back in
milliseconds through 127.0.0.53.
